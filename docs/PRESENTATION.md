## 1. Что за продукт (30 секунд, для начала презентации)

«Сходим?» — бот и мини-приложение в MAX для держателей Пушкинской карты
14–22 лет. Проблема: лимит карты сгорает 31 декабря, а подобрать событие
по остатку и возрасту и быстро собрать компанию — неудобно, разбросано по
разным чатам и приложениям. Продукт: бот за 3 вопроса узнаёт остаток,
кино-лимит и возраст, мини-приложение показывает только то, что реально
можно купить и на что пропустят по возрасту, и позволяет позвать друга
одной кнопкой — в том числе через нативный шеринг MAX в любой контакт.

Трек: «Досуг и развлечения».

## 2. Сценарий демо (по порядку, ~4–5 минут)

Сценарии ниже — на основе `docs/skhodim_tz.md` (§5), дополнены тем, что
реально реализовано сверх ТЗ.

**A. Онбординг и подборка**
1. Открой бота в MAX → нажми Start/«Начать».
2. Бот сразу спрашивает остаток (не нужно ничего писать самому, вопрос
   приходит первым сообщением) — введи `3200`.
3. Далее кино-лимит — введи `800`, затем возраст — введи `17`.
4. Бот подтверждает профиль. Нажми кнопку «Открыть Сходим?» — откроется
   мини-приложение прямо внутри MAX (не браузер).
5. Сверху — карта всех подходящих событий (не только приглашений), список
   карточек ниже. Покажи фильтр «после 18:00» — список сужается.
6. Найди событие с несколькими сеансами (например «Щелкунчик» или
   «Чайка» на тестовых данных) — под названием будут чипы с разным
   временем и ценой, можно переключать без ухода с карточки.

**B/C. Приглашение и раздел «Зовут»**
1. На карточке события нажми «Отправить событие».
2. Внутри настоящего MAX сверху будет кнопка **«Поделиться через MAX»** —
   открывает нативный экран пересылки MAX, где можно выбрать любой
   реальный контакт или групповой чат (не только тех, кто уже писал
   боту) — это стоит подчеркнуть отдельно, показывает расширенное
   использование возможностей MAX.
3. Ниже — список контактов, уже знакомых боту, плюс поле для
   необязательного комментария («давай сходим, я угощаю»). Выбери
   получателя, впиши комментарий, отправь.
4. Получатель получит **личное сообщение от бота** с эмодзи-карточкой:
   кто зовёт, куда, во сколько и комментарий, плюс кнопка «Смотреть в
   Сходим?».
5. На вкладке «Зовут» у получателя появится значок с числом новых
   приглашений. Открой — карточка видна с пометкой «помещается» или
   «не хватает N ₽», подписано, кто зовёт, и комментарий.
6. Нажми «Иду» — статус меняется, виден всем. Если хочешь показать
   «Предложить другое время» — оно подтянет реальные другие сеансы этого
   же события, если они есть, а не просто попросит ввести дату руками.

**D. Покупка**
1. На карточке нажми «Купить» — переход на внешнюю страницу продавца
   (заглушка/реальная ссылка в зависимости от события).
2. Вернись, нажми «Купил» — остаток в профиле уменьшается на цену
   выбранного сеанса.

## 3. Что говорить про технологии (если спросят «как устроено»)

- Бот — официальный MAX Bot API (`@maxhub/max-bot-api`), long polling, не
  вебхук. Реально зарегистрирован через business.max.ru, не эмуляция.
- Мини-приложение — React/TypeScript, открывается кнопкой бота прямо в
  вебвью MAX, подключает официальную библиотеку **MAX Bridge**
  (`window.WebApp`, dev.max.ru/docs/webapps/bridge) для нативного шеринга
  и для чтения id реального пользователя — не только «Open App», а
  двусторонняя интеграция с платформой.
- Бэкенд — Node.js/Fastify, PostgreSQL, свой REST API описан по OpenAPI
  3.0 (`server/openapi.yaml`). Афиша — публичный бесплатный API KudaGo
  (Москва + Казань), с дедупликацией почти-дублей (нечёткое сравнение
  названий + близость площадки + окно по времени) и группировкой разных
  сеансов одного события в одну карточку.
- Весь стек поднимается одной командой `docker compose up --build`
  (сервер + мини-апп + БД), без ручной настройки.
- Приватность по замыслу: без ФИО (имя подтягивается автоматически из
  самого MAX, не спрашивается как вопрос), без телефона, паспорта, номера
  карты; возраст хранится диапазоном (14-15/16-17/18-22), не датой
  рождения.

## 4. Что честно не сделано — если спросят, не отпираться

Жюри может спросить про пробелы из ТЗ. Лучше проговорить самим, чем дать
поймать на вопросе:

- **PRO.Культура.РФ (официальный источник) не подключён** — партнёрский
  доступ не выдан на момент хакатона. Вместо него — публичный KudaGo,
  адаптер под PRO.Культура.РФ уже готов, просто нет ключа партнёра.
- **Пересылка через MAX Bridge не создаёт запись в «Зовут»** у того, кому
  переслали — MAX не сообщает мини-приложению, куда именно ушла карточка.
  Трекинг статусов (Иду/Не могу) работает только для приглашений через
  список контактов бота, не через нативный шеринг.
- **Нет напоминаний** (за 30/7 дней до 31 декабря) и «дня похода» — это
  уровень Should/Could, сознательно оставлено на после хакатона.
- **Нет фильтра по абсолютной цене и по станции метро/району** — есть
  функционально более широкая замена: фильтр «Радиус» (работает в любом
  городе, не только Москве).
- Полный список — `README.md`, разделы «Сознательно не реализовано» и
  «Пробелы против ТЗ».

## 5. Если что-то сломалось во время демо

- **Бот не отвечает / мини-апп не открывается** — почти всегда означает,
  что Render-сервис уснул. Открой `https://skhodim-server.onrender.com/events`
  в браузере, подожди ответа (до минуты), попробуй снова.
- **В мини-приложении пусто / мало событий** — KudaGo (внешний бесплатный
  API) иногда недоступен или отвечает медленно. Сервер в этом случае сам
  переключается на встроенный тестовый срез (81 событие) — это не баг,
  а штатное поведение (`fetchWithFallback` в `server/src/db/seed.ts`).
  Если пусто совсем — перезапусти сервис в Render Dashboard
  (Manual Deploy → Deploy latest commit), `seed` пересоздаст данные.
- **Кнопка «Открыть Сходим?» открывает не вебвью, а внешний браузер** —
  проверь, что открываешь именно из-под бота в MAX (не по ссылке из
  другого источника).
- **Кнопки «Поделиться через MAX» не видно** — она сознательно скрыта
  везде, кроме настоящего MAX-клиента (в браузере/локальной разработке её
  не будет — это ожидаемо, не баг).
